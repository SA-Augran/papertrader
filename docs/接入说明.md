# 接入自己的 Agent

## 运行方式

本发行版是本机单用户服务。账户服务持有数据库，网页、HTTP 与 MCP 共用这一个账户。每个数据目录同一时刻只允许运行一个服务实例，默认端口 8322。

Python 3.9 及以上可运行账户和网页。可选 MCP 适配器需要 Python 3.11 及以上。模型密钥由宿主或账户运行器自行配置。

## 已有 Agent

安装并运行。

```sh
python -m pip install -e ".[realmarket]"
python -m papertrader serve --mode external --data-dir ./account
```

浏览器打开终端显示的本机地址，输入 Account token。令牌用于账户访问，不能使用模型 API 密钥代替。

启动命令增加 --open 可自动打开本机浏览器并连接账户，免去手工粘贴。浏览器取得令牌后立即清理地址片段，只在当前会话保存。

服务每天在上海时间 19:30 后尝试更新行情并准备任务，每 10 分钟检查一次。外部 Agent 宿主需要定时获取任务，自行完成推理后提交，MCP 连接不会自动唤醒 Agent。

首次启动从最新有效交易日经营，不自动倒推买卖。周末、决策窗口开启前、今日行情缺失或账户暂停时不会建立新任务。市场刷新失败时暂停新决策，并在面板显示错误。实时服务不自动切换合成行情。

## HTTP 最小流程

请求设置 Authorization 为 Bearer 后接账户令牌。

| 方法与路径 | 用途 |
|---|---|
| GET /api/state | 账户、行情日期、持仓、规则、决策、学习记录 |
| GET /api/context | 服务器保存的当日任务、快照、策略授权与可用动作 |
| POST /api/submit | 按 task_id 提交 proposal |
| GET /api/events?since=0 | 按决策 ID 增量取得已完成记录和反馈 |
| POST /api/commitment | 指定 code、quote、可选 through，明确等待承诺 |
| POST /api/revise | 指定 id、reason，记录有理由的改口 |
| POST /api/observation | 提交 text、source 作为外部背景 |
| POST /api/recheck | 指定 decision_id、可选 ignore_commitment，复算原检查 |
| POST /api/pause | 用户管理 paused 布尔值 |
| POST /api/tick | 手动检查当日任务，沙盒可手动执行本地策略 |

submit 示例。

```json
{
  "task_id": "从 context 得到的任务标识",
  "proposal": {
    "action": "hold",
    "code": "",
    "weight": 0,
    "reason": "今天的条件尚不足以开仓。"
  }
}
```

buy 的 code 从 allowed_actions.buy 选取，weight 是总资产目标比例。sell 使用已有持仓，整仓退出，weight 填 0。hold 可以不指定标的。

宿主应先保存 task_id 与原提案，再发请求。断线后重复提交相同提案返回原记录，改成另一个提案会得到 409。日期变化后未提交的旧任务过期。服务器重新检查当前承诺和持仓，客户端填入策略标签不能绕过授权。

响应中的 brain 区分 external、primary、secondary 与本地策略。outcome.feedback 出现时，才有整轮平仓的策略归因。

examples/host_agent.py 提供标准库调用示例，其默认判断为观望，用户替换 your_agent 函数即可使用自己的推理流程。

## MCP 配置

先启动 HTTP 账户服务，再安装可选适配器。

```sh
python -m pip install -e ".[mcp]"
python -m papertrader mcp
```

在支持 stdio MCP 的 Agent 宿主中使用下列配置，将 python 改为已安装本项目的解释器绝对路径，并填自己的令牌。

```json
{
  "mcpServers": {
    "papertrader": {
      "command": "python",
      "args": ["-m", "papertrader", "mcp"],
      "env": {
        "PAPERTRADER_URL": "http://127.0.0.1:8322",
        "PAPERTRADER_TOKEN": "替换为账户访问令牌"
      }
    }
  }
}
```

适配器提供 account_state、decision_context、submit_decision、events_since、record_commitment、revise_commitment、submit_observation、recheck_decision 八个工具。它调用同一个 HTTP 服务，不另开数据库或后台决策器。远程托管与多用户授权不在当前范围内。

## 给宿主的接入指令

你拥有一个模拟账户。决策窗口开启后先读取 decision_context，以其中的事实、候选授权和承诺判断。你可以观望。选择行动后保存 task_id 和提案，再调用 submit_decision。网络失败时重试相同提案。不要根据持仓浮盈宣称已获得成功样本。

宿主可将自己的检索内容作为 observation 提交，服务保存接收时间与来源。已经保存的当日任务不会因随后提交的信息自动重写，下一任务才会看到新背景。历史任务不注入之后接收的信息。

## 记忆回流

events_since 返回已完成决策与 outcome，其中可能包含平仓反馈。宿主按 ID 顺序处理，成功写入自己的记忆后才推进游标。建议用账户标识和决策 ID 构造去重键，并把游标持久化。服务不接触用户的私人记忆数据库。

当前事件源以完成决策为单位，承诺和背景由各自接口管理。日记是基于记录生成的简短事实，不模拟固定角色的情绪。自然语言风格由宿主决定。

## 内置模型运行器

不使用已有 Agent 时，安装 llm 与 realmarket 依赖，按 .env.example 在账户目录放置 .env，然后以 --mode model 启动。主备模型密钥从环境变量或账户目录 .env 读取。默认无私人角色，可用 --persona 指定用户自己持有的文本。

--mode local 显式使用本地规则，不调用模型。这一来源会进入记录。切换模式或行情来源应新建账户目录，避免把不同实验和真实运行混在一起。

## 暂停、恢复与备份

面板暂停状态保存在账户中，重启后保持。停止服务后复制整个数据目录即可备份，数据库中包含访问令牌，应作为私人文件保管。恢复使用复制后的目录，不能同时启动两个实例。

关闭进程期间没有持续唤醒 Agent。恢复后服务从当前交易日继续，不把停机期间的历史机会冒充当时决策。Windows 任务计划或 Linux 服务可由用户配置常驻启动。

服务日线简化成交使用当日收盘价，每边 10 基点费用，允许碎股。独立评测脚本另支持下一收盘成交。复核仅重算保存的规则检查，不计算假设交易盈亏。
